# Sofia 座位分配系统

基于 Flask 的教室座位安排工具。录入男女学号列表，设置排数和列数，程序按性别和约束条件生成座位表。默认只监听本机 `127.0.0.1`，局域网内其他设备无法访问。

## 功能

- 按区间或单个学号录入学生名单，男女分开填写。
- 按排数、列数生成座位网格，同一排相邻的两列组成一张课桌。
- 控制男女是否混坐。不勾选混坐时，同桌与已落座的一方保持同性别。
- 指定某个学号坐在固定位置，例如学号 5 坐第 2 排第 2 列。
- 指定两个学号必须同桌。
- 结果页用颜色和标签区分座位类型，标出指定座位、同桌、普通座位和空座。
- 浏览器本地记住上次的学号列表和排座参数。

## 环境要求

- Windows、macOS 或 Linux
- Python 3.8 或更新版本
- Flask（见 `requirements.txt`）
- 现代浏览器

## 安装与启动

在项目目录打开终端：

    python -m venv .venv

Windows PowerShell：

    .venv\Scripts\Activate.ps1
    python -m pip install -r requirements.txt
    python app.py

macOS / Linux：

    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python app.py

浏览器打开：

    http://127.0.0.1:5039/seats/login

停止服务时，在运行窗口按 `Ctrl+C`。

默认端口是 5039，只绑定 `127.0.0.1`。端口被占用时，启动前换一个：

    $env:SEATS_PORT = "5040"
    python app.py

访问地址相应变成 `http://127.0.0.1:5040/seats/login`。服务仍然只绑定本机回环地址。

会话密钥默认在每次启动时随机生成，重启会让已登录的浏览器会话失效。需要固定密钥时设置环境变量：

    $env:SEATS_SECRET_KEY = "换成一串自己的随机字符"
    python app.py

`seats_app.py` 是早期单文件版本留下的入口，现在指向同一个应用，运行效果与 `app.py` 一致。新用法请直接用 `app.py`。

## 使用说明

### 学号输入

男女各填一个学号列表，两种写法可以混用，用英文逗号分隔：

| 写法 | 含义 |
| --- | --- |
| `1-20` | 1 号到 20 号 |
| `45,47` | 45 号和 47 号 |
| `1-20,45,47` | 上面两种组合 |

两个列表至少要填一个。提交后进入排座页面。

### 座位参数

- **列数**：默认 8，输入框提示建议 6-10。**请填偶数**，原因见「已知限制」。
- **排数**：默认 5，提示建议 4-8。当 `排数 × 列数` 小于学生总数时，程序按 `学生数 ÷ 列数` 向上取整自动增加排数。
- **男女混坐**：勾选后同桌不限性别。不勾选时，同桌必须与已落座的一方同性别。

### 约束条件

三个输入框都留空或填 `0` 表示不启用约束。多条约束之间用英文分号 `;` 分隔。

| 约束 | 格式 | 示例 | 含义 |
| --- | --- | --- | --- |
| 指定座位 | `学号=(排,列)` | `5=(2,2);10=(1,1)` | 学号 5 坐第 2 排第 2 列，学号 10 坐第 1 排第 1 列 |
| 必须同桌 | `学号,学号` | `1,2;5,7` | 1 号和 2 号同桌，5 号和 7 号同桌 |
| 不能同桌 | `学号,学号` | `3,4;6,9` | 3 号和 4 号不能同桌（**当前不生效**，见「已知限制」） |

指定座位的排、列都从 1 开始数，与结果页表头的编号一致。

### 结果页图例

| 标记 | 颜色 | 含义 |
| --- | --- | --- |
| 指定 | 特殊色 | 该学号由「指定座位」约束确定 |
| 同桌 | 同桌色 | 该学号出现在「必须同桌」里 |
| 分离 | 分离色 | 该学号出现在「不能同桌」里，只是标记 |
| 普通 | 常规色 | 没有命中任何约束 |
| 空座 | 灰色 | 该位置没有分到学生 |

表头横向标列号，第一列纵向标「第 N 排」，编号都从 1 开始。

### 数据保存

排座页面的列数、排数、混坐开关和三个约束输入框都存进浏览器 localStorage，下次打开自动回填。登录页的「记住学号列表，下次自动填充」勾选后保存男女学号，取消勾选立即清除。这些数据只存在本地浏览器里，换浏览器或清理浏览数据后需要重新填写。

## 座位分配流程

`seats_bp/routes.py` 的 `seat_assign()` 按以下顺序执行：

1. 解析学号列表，构建学生对象，每人带学号和性别两个字段。
2. 座位不够时增加排数，保证容量不小于学生总数。
3. 先落「指定座位」。学号存在、行列在范围内、目标位置为空，三条都满足才落座。
4. 把同一排相邻的两列切成一张课桌，例如第 1、2 列一张，第 3、4 列一张。
5. 顺序扫描课桌，把「必须同桌」的一对放进第一张空桌。
6. 剩余学生打乱顺序后填充空位。不勾选混坐时，先找出与已落座一方同性别的学生配对。
7. 给每个已落座的学生补上 `is_special`、`is_must_share`、`is_must_diff` 三个标记，供模板选颜色。
8. 最后把所有学生按「从上到下、从左到右」重新密排，空位集中到表格末尾。

第 8 步是理解「已知限制」的关键：这一步按行优先整齐重排，不再照顾课桌配对和指定座位的坐标。表格本身就填满时它是空操作；一旦中间存在空位，位置就会整体错动。

## 生产部署

本机默认用 Flask 自带的开发服务器。部署到服务器时换用 waitress：

    nohup waitress-serve --port=5039 --threads=4 app:app &

`app:app` 指向 `app.py` 里的 Flask 对象。常用运维命令：

    ps aux | grep waitress-serve    # 查看进程
    kill <PID>                      # 停止单个进程
    pkill -f waitress-serve         # 停止全部
    kill -9 <PID>                   # 强制停止

`app.py` 固定绑定 `127.0.0.1`。要让局域网内其他设备访问，改用 waitress 并显式指定监听地址：

    waitress-serve --host=0.0.0.0 --port=5039 --threads=4 app:app

把这套系统挂在已有 Flask 应用里时，注册蓝图即可：

    from seats_bp import seats_bp
    app.register_blueprint(seats_bp, url_prefix="/seats")

蓝图内部用 `seats.xxx` 形式的端点名，因此 `url_prefix` 必须和模板里的 `url_for` 对得上，直接放在 `/seats` 下即可。

## 已知限制

以下问题在当前代码里真实存在，使用前请了解。前两条建议优先处理。

**一、不勾选混坐时，性别人数不平衡会漏学生。**
填充空桌时先随机取一名学生，再找一名同性别的配对。如果剩余学生里没有同性别的，这个座位留空，而那名落单的学生不会被放到后面的空桌，直接从这个座位上消失。结果页看不出少了人。
实测：1 名男生、3 名女生，2 张课桌共 4 个座位，不勾选混坐，连跑 8 次，每次都有 1 名学生没有出现在座位表里，同时表格里空着一个座位。

**二、「不能同桌」不生效。**
`must_diff` 只在解析后算出标记，填充循环里从未检查它。被约束的两名学生可能被排成同桌。结果页仍会给这两人的学号加上「分离」标签，看起来像已经生效。实测中「3,4 不能同桌」的约束下，3 号和 4 号多次被排在同一张课桌。

**三、列数填奇数时，每排最后一个座位是单人桌。**
课桌按「相邻两列一张」切分，列数为奇数时最后一列不参与配对，成为没有同桌的单座。同时该列在写回时不受课桌逻辑管理，中间产生空位，触发第 8 步的整体重排。重排会打乱课桌配对，也会让学生离开「指定座位」指定的坐标。排座参数里把列数填成偶数可以避开这个问题。

**四、指定座位冲突时静默跳过。**
学号不在名单里、行列超出范围、目标位置已被占用，这三种情况都会让这条约束被直接忽略，页面上没有任何提示。实测同一条 `(1,1)` 位置分别指定给两个学号时，只有先解析到的那个生效，另一个被丢弃。

**五、学号重复不去重。**
同一个学号同时填进男生列表和女生列表，或在一个列表里写两遍，程序会生成两条学生记录，排座时占两个座位。
